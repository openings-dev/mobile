# Design System

> Index the durable Openings visual and interaction rules for native mobile surfaces.

## Authority

The established Openings brand and product contracts come from the public web
product. The public `@openingshq/design-tokens` package is the mobile runtime source
for shared primitives, semantic themes, typography, shape, spacing, NativeWind
variables, and utility mappings. Mobile components implement those foundations with
native layout and interaction patterns.

Do not copy web markup or desktop composition literally. Preserve the same identity,
content hierarchy, semantic roles, locale coverage, and claims boundary while using
safe areas, native navigation, touch targets, Dynamic Type, screen-reader semantics,
keyboard behavior, and platform conventions.

## Durable rules

- Use one shared token system across web and mobile.
- Keep the Openings identity monochrome when official brand artwork is introduced.
- Use Figtree and semantic hierarchy instead of excessive decorative containers.
- Keep Brand Mint controlled and purposeful.
- Make public opportunities, communities, authors, repository source, tags, and
  filters the visual subject; do not add generic technology decoration.
- Preserve light and dark hierarchy, all six locales, responsive reflow, and
  accessible native interaction.
- Do not copy third-party logos, illustrations, layouts, or proprietary copy.
- Do not describe an unimplemented logo asset, icon system, or component library as
  available in the mobile repository.
